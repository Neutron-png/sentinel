# Sentinel Users

Version: 0.1

Status: Draft

---

# Overview

This document defines the users Sentinel is designed for.

Sentinel is built around the needs of security researchers who perform application security assessments and need a structured workflow to manage testing, verification, evidence, and reporting.

The goal is not to define users only by job title, but by their problems, responsibilities, and expectations.

---

# Primary Users

---

# 1. Security Researcher

## Description

A person who performs security assessments, vulnerability research, penetration testing, or bug bounty activities.

## Experience Levels

Can range from beginner to advanced.

---

## Goals

- Perform complete security assessments.
- Follow structured methodologies.
- Discover and verify security issues.
- Maintain organized evidence.
- Produce clear reports.

---

## Pain Points

- Forgetting important test cases.
- Losing track of testing progress.
- Managing evidence manually.
- Switching between multiple tools.
- Spending too much time creating reports.

---

## How Sentinel Helps

Sentinel provides:

- Assessment workflows.
- Testing guidance.
- Evidence organization.
- Verification tracking.
- Reporting support.

---

# 2. Penetration Tester

## Description

A security professional performing authorized assessments for organizations.

---

## Goals

- Complete assessments efficiently.
- Maintain consistency between projects.
- Provide professional deliverables.
- Make testing activities reviewable.

---

## Pain Points

- Repeating the same setup work.
- Maintaining documentation quality.
- Tracking assessment scope.
- Reviewing completed and incomplete areas.

---

## How Sentinel Helps

Sentinel provides:

- Repeatable workflows.
- Assessment history.
- Structured evidence.
- Standardized reports.

---

# 3. Security Learner

## Description

A developer, student, or beginner learning application security concepts.

---

## Goals

- Understand security testing methodologies.
- Learn why tests are performed.
- Practice structured assessments.

---

## Pain Points

- Not knowing where to start.
- Lack of testing structure.
- Confusion between tools and methodologies.
- Difficulty understanding security results.

---

## How Sentinel Helps

Sentinel provides:

- Explanations.
- References.
- Guided workflows.
- Clear testing objectives.

---

# Secondary Users

---

# 4. Security Team Reviewer

## Description

A person reviewing security assessment results.

Examples:

- Security managers.
- Application security engineers.
- Team leads.

---

## Goals

- Understand assessment coverage.
- Review evidence quality.
- Validate findings.

---

## Pain Points

- Incomplete reports.
- Missing evidence.
- Unclear testing process.

---

## How Sentinel Helps

Sentinel provides:

- Structured reports.
- Assessment history.
- Evidence traceability.

---

# User Levels

## Beginner

Needs:

- More explanations.
- Clear guidance.
- References.
- Learning support.

---

## Intermediate

Needs:

- Workflow organization.
- Faster execution.
- Better tracking.

---

## Advanced

Needs:

- Flexibility.
- Custom workflows.
- Less interruption.
- Detailed evidence management.

---

# User Principles

Sentinel should:

- Respect different experience levels.
- Never assume expertise.
- Never hide important information.
- Allow experienced users to move faster.
- Help beginners understand the reasoning behind actions.

---

# Primary User Focus

The first version of Sentinel focuses on:

> Security researchers performing web application security assessments.

Other users and security domains may be supported later.
