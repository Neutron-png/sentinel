# Sentinel Non-Goals

Version: 0.1

Status: Draft

---

# Overview

This document defines what Sentinel intentionally will not become.

Defining non-goals is important to prevent uncontrolled scope expansion and to keep the project focused on solving the original problem.

Sentinel is designed to improve the penetration testing workflow, not to replace security professionals or existing security ecosystems.

---

# 1. Sentinel Is Not an Autonomous Pentester

Sentinel will not attempt to perform a complete penetration test without human involvement.

It will not:

- Make final security decisions automatically.
- Determine impact without researcher input.
- Replace human reasoning.
- Operate without user awareness and control.

Human expertise remains a core part of the process.

---

# 2. Sentinel Is Not a Vulnerability Scanner

Sentinel is not designed to compete as a traditional vulnerability scanner.

It will not focus on:

- Finding the maximum number of possible issues.
- Running thousands of automated checks blindly.
- Producing large amounts of unverified results.

Sentinel prioritizes:

- Context.
- Methodology.
- Verification.
- Evidence.

---

# 3. Sentinel Is Not an Exploitation Framework

Sentinel will not become a replacement for exploitation frameworks.

It will not focus on:

- Automated exploitation chains.
- Offensive payload libraries.
- Weaponized attack automation.

The focus is assessment workflow and verification.

---

# 4. Sentinel Is Not a Replacement for Existing Security Tools

Sentinel will not replace specialized tools such as:

- Proxy tools.
- Network scanners.
- Static analysis tools.
- Mobile analysis tools.

Instead, Sentinel should work as an organizing layer around security workflows.

---

# 5. Sentinel Is Not an AI Security Agent

AI is not a core dependency of Sentinel.

The system should not rely on AI to:

- Decide vulnerabilities.
- Generate security conclusions.
- Replace methodology.
- Replace verification.

Security decisions should be based on:

- Defined workflows.
- Security references.
- Collected evidence.
- Researcher judgment.

---

# 6. Sentinel Is Not a Learning Platform

Although Sentinel should be educational, it is not intended to replace:

- Security courses.
- Certifications.
- Books.
- Professional training.

Educational explanations exist to support the workflow.

---

# 7. Sentinel Is Not Limited to One Security Domain Forever

The first focus is web application security.

However, the architecture should not prevent future expansion into:

- API security.
- Mobile security.
- Game security.
- Other application security areas.

Future expansion should happen only after the core workflow foundation is stable.

---

# 8. Sentinel Is Not a "Magic Button"

A user should never expect:

"Run Sentinel → Receive Perfect Security Report"

Security testing requires:

- Understanding.
- Investigation.
- Verification.
- Decision making.

Sentinel improves the process; it does not remove the process.

---

# Summary

Sentinel exists to provide structure around security assessments.

It does not aim to:

- Replace researchers.
- Replace tools.
- Replace expertise.
- Automate security judgment.

Its value comes from helping humans perform better security work.
